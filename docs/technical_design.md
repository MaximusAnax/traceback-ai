## 1. System Architecture: The "Async Maintenance Pipeline"

To ensure reliability, TraceBack decoupling the **Ingestion** of error signals from the **Inference** of fixes using a standard producer-consumer pattern.

### 1.1 The Job Orchestrator (BullMQ + Redis)

- **The Producer:** A lightweight TypeScript service (Fastify) that validates Sentry/GitHub webhooks. It enqueues a `MaintenanceJob` containing the stack trace and repository metadata.
- **The Queue:** Redis-backed BullMQ manages retries and concurrency. Critical bugs (e.g., CVSS 10.0) can be prioritized using BullMQ’s priority levels (priority 1 = highest).
- **The Worker:** A Node.js worker that instantiates the `@cursor/sdk` to launch an agent session for each job.

### 1.2 The Sandbox Strategy (Hybrid E2B & Cursor Cloud)

You do not have to pick between E2B and Cursor Cloud; each serves a distinct role in a production maintenance workflow:

- **E2B (The "Reproduction" Lab):** Use E2B sandboxes for the initial reproduction step. Their sub-200ms cold starts and Firecracker microVM isolation make them ideal for running untrusted logic snippets or small synthetic tests to "prove" the bug exists.
- **Cursor Cloud (The "Implementation" Factory):** Use the Cursor SDK’s native cloud runtime for the actual code modifications. This provides the agent with a full Ubuntu VM, a repo clone, and an **integrated browser** for visual verification of frontend fixes.

## 3. The "SDK Wrapper" Agent Loop

Since we are wrapping the Cursor SDK, the core logic is implemented in a few lines of TypeScript using the `Agent.create` and `agent.send` methods.

### 3.1 Step-by-Step Logic

1. **Onboard:** The worker calls `Agent.create({ model: { id: "composer-2" }, runtime: "cloud" })`. The SDK handles the VM provisioning and repository cloning.
2. **Analyze:** The agent uses Cursor's native AST-based indexing to find the error origin: `"Search @codebase for the cause of this Sentry stacktrace: [Payload]"`.
3. **Reproduce (Optional E2B Fallback):** If the fix requires complex environment state, the agent calls an **E2B tool** to attempt a reproduction in a clean container.
4. **Implement:** The agent performs the fix using the **GPT-5.4 Codex** variant, which is specifically trained for surgical edits on existing codebases.
5. **Audit:** A final pass ensures the fix adheres to your `.cursor/rules/*.mdc` files, specifically checking for "patchy edits" or security regressions.

## 4. Open-Source vs. Enterprise SaaS Moat

### 4.1 TraceBack Core (The Wrapper CLI)

The open-source core will be a CLI tool that users run in their own environment.

- **Transparency:** Users can audit exactly how TraceBack structures its prompts and manages context.
- **BYOK:** Users provide their own `CURSOR_API_KEY` and `OPENAI_API_KEY`.

### 4.2 TraceBack SaaS (The Governance Layer)

The commercial product sells the infrastructure and compliance required by enterprises.

- **Persistence:** Use BullMQ's "Delayed Jobs" and "Retries" to handle long-running sessions that might take 30+ minutes.
- **Comprehension Artifacts:** The SaaS dashboard hosts the **video demos** and **decision logs** generated by the Cloud Agents, allowing leads to review 20 PRs in the time it usually takes to review one.
- **Identity Binding:** Every agent action is signed with the enterprise user’s identity (via OIDC) for audit trails.
